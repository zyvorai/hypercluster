The Problem

Deploying and maintaining a production Kubernetes cluster is still painful:

  • Tool sprawl — kubeadm + Ansible + Helm + custom scripts
  • Inventory hell — YAML by hand, per-cluster, error-prone
  • Day-2 forgotten — scaling and upgrades need separate runbooks
  • kubeconfig chaos — scattered, unpatched, not merged
  • No local testing — cloud VMs or expensive hardware needed
  • No VM workloads — KubeVirt setup left as an exercise
Current reality:

10+ commands
to get a cluster

❌ No single lifecycle tool

Architecture

cluster.conf ──► hypercluster ──► Kubespray
│
├─ clone Kubespray (version-locked)
├─ generate hosts.yaml
├─ generate group_vars
├─ run cluster.yml
├─ fetch + patch kubeconfig
└─ install KubeVirt + CDI

Repository Layout

hypercluster/
  hypercluster        # CLI entry point
  cluster.conf        # Your config (one file)
  lib/
    log.sh            # Emoji logging
    preflight.sh      # SSH + tool checks
    inventory.sh      # hosts.yaml generation
    kubespray.sh      # Clone + run playbooks
    kubeconfig.sh     # Fetch + patch + merge
  scripts/
    remote-k8s-deploy.sh     # Standalone k3s/kubeadm
    setup-macos.sh    # macOS dev setup
    test-podman.sh    # Local container testing

What hypercluster Does NOT Do

hypercluster is a thin shell wrapper.
It does zero Kubernetes work itself.

Every operation delegates to a
Kubespray Ansible playbook.

Nodes Required

  • Any bare-metal or VM with Linux
  • SSH access (key auth, root)
  • No cloud provider dependency
  • Works air-gapped

Tested On

AlmaLinux 9 Rocky 9 Ubuntu 22.04 RHEL 9 Debian 12

One Config File

# cluster.conf
CLUSTER_NAME="prod-k8s"
KUBESPRAY_VERSION="v2.30.0"

# Kubernetes
KUBE_VERSION="v1.32.0"
CONTAINER_MANAGER="podman"
CNI_PLUGIN="cilium"

# Nodes (space-separated IPs)
CONTROL_PLANE_IPS="10.0.1.10"
WORKER_IPS="10.0.1.11 10.0.1.12 10.0.1.13"

# SSH
SSH_USER="root"
SSH_KEY="$HOME/.ssh/id_cluster"
SSH_PORT=22

# Add-ons
METRICS_SERVER_ENABLED="true"
INGRESS_NGINX_ENABLED="false"

# KubeVirt — VM workloads
KUBEVIRT_ENABLED="true"
KUBEVIRT_VERSION="v1.3.1"
CDI_VERSION="v1.59.0"

# Output
KUBECONFIG_OUTPUT="$HOME/.kube/prod-k8s.yaml"

Then just run:

# Check everything first
./hypercluster preflight

# Full cluster bootstrap
./hypercluster deploy

# That's it. You get:
# ✅  Kubernetes cluster
# ✅  Cilium CNI + Hubble
# ✅  kubeconfig auto-fetched
# ✅  KubeVirt operator
# ✅  CDI for disk images
No Ansible knowledge required.
No inventory.ini, no group_vars, no playbook flags.
All of that is generated automatically.

Command Reference

CommandWhat it does
hypercluster init Clone Kubespray (version-locked) and generate hosts.yaml + group_vars
hypercluster preflight Verify Ansible, Python, kubectl are installed; check SSH key permissions and node reachability
hypercluster deploy Full bootstrap: preflight → init → cluster.yml → kubeconfig → KubeVirt
hypercluster scale Add worker nodes listed in conf — runs scale.yml, existing workloads untouched
hypercluster upgrade Rolling Kubernetes upgrade via upgrade_cluster.yml — one node at a time
hypercluster remove-node <name> Gracefully drain and remove a node; -f for ungraceful removal
hypercluster fetch-kubeconfig Pull admin.conf, patch 127.0.0.1 → master IP, save + merge into ~/.kube/config
hypercluster install-kubevirt Deploy KubeVirt operator + CDI on an existing cluster (also runs post-deploy automatically)
hypercluster status Run kubectl get nodes -o wide against the cluster
hypercluster destroy Run reset.yml — tears down cluster (requires typed confirmation)

hypercluster deploys Cilium as the default CNI.
eBPF-powered networking, security, and observability — out of the box.

Hubble UI — Network Observability

  • Real-time flow visualization
  • Per-namespace traffic maps
  • Policy verdict monitoring
  • Service dependency graphs

Cilium CLI — Installed by Default

# Check Cilium status
cilium status

# Connectivity test
cilium connectivity test

# Enable Hubble UI
cilium hubble enable --ui

# Port-forward Hubble
kubectl -n kube-system \
  port-forward svc/hubble-ui 12000:80

What Kubespray Generates

# group_vars/k8s_cluster/k8s-cluster.yml
kube_network_plugin: cilium
cilium_hubble_enabled: true
cilium_enable_bpf_masquerade: true

To switch CNI: set CNI_PLUGIN="calico" in cluster.conf

KubeVirt — VM Workloads on Kubernetes

Run Windows and Linux VMs alongside containers
on the same Kubernetes cluster — using familiar kubectl.

What Gets Installed

ComponentPurpose
KubeVirt OperatorVM lifecycle management
CDIContainerized Data Importer — disk image uploads
virt-launcherPod wrapping each VM (QEMU inside)
virtctl (CLI)VM console, VNC, SSH, start/stop

Supported VM Types

Ubuntu RHEL / Rocky AlmaLinux CentOS Windows 10/11 Windows Server Any QEMU-compatible image

Enable in cluster.conf

KUBEVIRT_ENABLED="true"
KUBEVIRT_VERSION="v1.3.1"
CDI_VERSION="v1.59.0"

Or install standalone

./hypercluster install-kubevirt

Manage VMs with virtctl

# Start / stop
virtctl start my-windows-vm
virtctl stop my-ubuntu-vm

# Connect to serial console
virtctl console my-ubuntu-vm

# SSH via VirtIO
virtctl ssh fedora@my-vm

# VNC (graphical)
virtctl vnc my-windows-vm

Standalone: remote-k8s-deploy.sh

A single-file bash deployer — no Kubespray, no Ansible, no Python. Ideal for quick k3s clusters or when Kubespray is overkill.

Configure

# Edit top of script
CLUSTER_NAME="prod"
MASTER_IP="10.0.1.10"
MASTER_USER="root"
MASTER_SSH_KEY="~/.ssh/id_rsa"
WORKERS=(
  "10.0.1.11|root|~/.ssh/id_rsa"
  "10.0.1.12|root|~/.ssh/id_rsa"
)
K8S_DISTRO="k3s"
SSH_PORT=22

Run

# Basic run
./scripts/remote-k8s-deploy.sh

# External config (no edit)
HC_CONFIG=my.conf \
  ./scripts/remote-k8s-deploy.sh

# Verify SSH only
./scripts/remote-k8s-deploy.sh --verify

# Help
./scripts/remote-k8s-deploy.sh --help

Features

  • k3s or kubeadm
  • Parallel worker install
  • OS auto-detection (cache)
  • Podman / Docker / none
  • kubeconfig fetch + merge
  • Idempotent — re-run safe
  • Bash 5 re-exec on macOS
Tested: AlmaLinux 9.7 with k3s v1.34
Node Ready in under 90s.

Day-2 Operations

Scale — Add Nodes

# cluster.conf
WORKER_IPS="10.0.1.11 10.0.1.12
            10.0.1.13 10.0.1.14"

# Run scale
./hypercluster scale
Kubespray's scale.yml only touches
new nodes — existing workloads
are not disrupted.

Upgrade — Rolling

# cluster.conf
KUBE_VERSION="v1.33.0"

# Run upgrade
./hypercluster upgrade
Kubespray drains each node before
upgrading — pods are rescheduled,
not killed.

Remove Node

# Graceful drain + remove
./hypercluster remove-node worker3

# Force (no drain)
./hypercluster -f remove-node worker3

kubeconfig Management

# Fetch from cluster
./hypercluster fetch-kubeconfig

# Merge all clusters
./hypercluster merge-kubeconfig

# Use it
export KUBECONFIG=\
  ~/.kube/prod-k8s.yaml
